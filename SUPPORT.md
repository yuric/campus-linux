# Getting help

## Something is broken

Open an issue using the **Bug report** template. Include the client version, which Campus
API you are pointed at, and steps to reproduce.

**Before you file:** if the client is showing something wrong that the API decides — which
providers exist, whether a credential works, what a failure means, what a stage is called —
the bug is probably in the API rather than in this client. Say so if you suspect it; that
routes it faster.

## Something should work differently

Open an issue using the **Feature request** template. Describe the situation, not the
solution — what is awkward or impossible today.

If the request needs this client to decide something new about the product, it needs an API
change first. That is not a rejection, but it changes where the work starts.

## You found a security problem

**Do not open an issue.** See [SECURITY.md](SECURITY.md).

## You want to contribute

See [CONTRIBUTING.md](CONTRIBUTING.md), and read it before writing code: this client has not
been started, so an issue is the place to begin.

## Response times

This is a small project. Issues are read, but there is no support SLA. Security reports are
the exception: acknowledged within 3 working days.
