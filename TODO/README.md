# Product requirements

[../PRD.md](../PRD.md) specifies the Linux product, parity inventory and delivery gates.
Future feature PRDs belong at `TODO/<feature-name>/PRD.md`.

Each feature PRD must name the user problem, scope, non-goals, overall parity IDs,
immutable source/API evidence, decisions versus proposals, repository dependencies,
acceptance tests, recovery/security/accessibility cases, delivery status and linked PRs.

A planning document is not evidence that a feature ships. Do not introduce another
feature PRD at the root or import production tasks from a draft without a separate execution request.
